Attention Batch-Safety Plan

Problem
- Current self-attention flattens batch and sequence into T = batch_size * train_seq_len.
- Qh and Kh are shaped [T, dh], and scores = Qh * Kh^T becomes [T, T].
- This causes cross-batch attention when training uses batch_size > 1.
- apply_causal_mask_inplace only enforces lower-triangular masking over the full [T, T] matrix.
- Result: sample 1 can attend to sample 0, sample 2 can attend to sample 0 and 1, etc.

Why This Matters
- Training semantics are wrong for independent samples in a batch.
- Loss can become unstable or misleading.
- Behavior can differ sharply between batch_size = 1 and batch_size > 1.

Goal
- Keep independent samples independent during attention.
- Produce per-batch attention of shape [B, S, S], not one global [T, T].
- Avoid a full tensor-system rewrite unless necessary.

Recommended First Fix
- Keep the existing 2D tensor/storage system.
- Treat token rows logically as B blocks of S rows, where:
  B = batch_size
  S = train_seq_len
  T = B * S
- In SelfAttention, operate per batch block instead of over the full flattened T rows.

Forward Pass Fix
1. Keep Q, K, V storage as [T, D].
2. For each head h:
   - Slice Qh, Kh, Vh as [T, dh].
3. For each batch block b:
   - Slice rows [b*S : (b+1)*S] from Qh, Kh, Vh.
   - Compute scores_b = Qh_b * Kh_b^T, shape [S, S].
   - Apply scale.
   - Apply causal mask on scores_b.
   - Softmax rows to weights_b.
   - Compute head_b = weights_b * Vh_b.
   - Copy head_b back into the corresponding rows of context_h.
4. Repeat for all heads.

Backward Pass Fix
1. Mirror the same per-batch slicing.
2. For each head h and batch block b:
   - dweights_b = dhead_b * Vh_b^T
   - dVh_b = weights_b^T * dhead_b
   - dscores_b = softmax backward
   - apply causal mask to dscores_b
   - dQh_b = dscores_b * Kh_b
   - dKh_b = dscores_b^T * Qh_b
3. Accumulate results back into the flattened [T, D] gradient buffers.

Masking Requirement
- Causal masking must be applied separately on each [S, S] block.
- Do not apply one global causal mask over [T, T].

Minimal Code Areas To Change
- src/model/self_attention.cpp
- Possibly helper slicing utilities if row-block slicing is awkward with current TensorView APIs.
- Possibly temporary tensor usage if current temp buffers assume only one [T, T] score matrix is live.

What Does Not Need To Change For The First Fix
- Parameter tensor shapes.
- Wqkv, Wo, FFN weights, embeddings.
- Backend ABI.
- General tensor rank support.
- Most of the trainer and optimizer code.

Suggested Validation
1. Run with batch_size = 1 and batch_size > 1 on the same tiny dataset.
2. Confirm loss curves become more consistent.
3. Add a debug check that attention for one batch block never reads rows outside that block.
4. Add a targeted unit/integration test:
   - B = 2, S = 3
   - verify scores for batch 0 are unaffected by values in batch 1
   - verify masking is block-local and causal

Longer-Term Ideal Design
- General rank-aware tensor views with shape + strides for N dimensions.
- Natural transformer shapes:
  hidden states [B, S, D]
  Q/K/V [B, H, S, dh]
  scores [B, H, S, S]
- Batched matmul and batch-aware masking kernels in the backend.
- Keep weights as 2D where natural.

Recommendation
- Implement the batch-sliced 2D fix first.
- Confirm loss and behavior improve.
- Only then consider a broader move toward rank-aware tensors or batched kernels.
